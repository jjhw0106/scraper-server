feat(scraper): 지원 내역 조회 API 구현 및 식별자 로직 최적화

- 조회 기능 구현:
  - `GET /scraper/history/:userId` 엔드포인트 추가
  - `getApplyHistory` 메서드 구현: MongoDB에서 특정 유저의 데이터를 최신순(`appliedAt: -1`)으로 조회
- 데이터 식별자(userId) 로직 간소화:
  - 서비스 메서드 시그니처에서 불필요한 `userId` 인자 제거
  - `credentials.id`를 내부 식별자로 직접 사용하도록 통합하여 코드 중복 제거
  - 컨트롤러에서 `body.id`를 서비스의 식별자로 바로 매핑하여 프론트엔드 연동 최적화
- 안정성 개선:
  - 리팩토링 과정에서 누락되었던 `saveScrapedData` DB 저장 로직 복구 및 검증
